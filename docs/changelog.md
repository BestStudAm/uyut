## 29 августа — Илья

### Карты переведены на Яндекс

- общий загрузчик lib/yandexMaps.ts: скрипт API подключается один раз на всё
  приложение, вторая вставка того же тега ломает уже созданные карты

  метки-ценники, подсветка при наведении, клик по метке прокручивает список

  страница продолжает работать
- leaflet и @types/leaflet удалены из зависимостей, после git pull нужен
  npm install в папке client

Ключ API не используется: Яндекс отдаёт карты и без него, хотя по их условиям
ключ нужен. Загрузчик подхватит NEXT_PUBLIC_YANDEX_MAPS_KEY, если его завести.
Изначально брали OpenStreetMap как гарантированно свободный, перешли ради
привычного пользователю вида.

### Часть Артёма: отзывы, карта на странице объекта, цена в брони

- таблица reviews, ручка GET /api/listings/:id/reviews, сидер наполняет
  2-4 отзыва на объявление, авторы и тексты внутри объявления не повторяются
- рейтинг и число отзывов считаются по самим отзывам, а не лежат отдельным
  числом, которое может разъехаться с реальностью
- блок отзывов на странице объекта и карта с меткой в блоке «Где находится»
- в бронь добавлены nights, price_per_night, service_fee, total: сумма
  фиксируется при оформлении. Иначе подорожание объявления задним числом
  меняло бы уже оформленные брони
- брони, созданные до появления полей, пересчитываются один раз при старте

Схема доезжает сама: недостающие колонки добавляются через ALTER TABLE при
запуске, существующая база не ломается.

## 27 августа — Илья

### Кабинет владельца (новое, сверх плана)

Раздела не было в MVP: в `plan.md` он записан в «сознательно не делаем». Взяли
дополнительно, поэтому из запаса на сокращение первыми уходят избранное и отзывы.

- `/my-listings` — свои объявления. Вкладки «Опубликованные», «Черновики»,
  «Снятые» со счётчиками. Снятие с публикации, возврат обратно, удаление
  черновика с подтверждением
- `/my-listings/new` и `/my-listings/:id` — форма размещения и редактирования:
  название, тип, комнаты, гости, площадь, район, адрес, цена, описание,
  удобства, правила, фотографии
- справа живое превью карточки и чеклист «Перед публикацией»
- фотографии уменьшаются в браузере до 900 пикселей и хранятся строкой
  `data:image`. Файлового хранилища нет, а без уменьшения запрос не проходит по
  размеру тела. Лимит тела на сервере поднят до 12 МБ
- обложку можно выбрать кликом по любой загруженной фотографии — она
  переставляется в начало списка
- черновик и публикация проверяются по-разному: черновику хватает названия и
  района, публикации нужны три фотографии, описание от 100 символов, цена и адрес

Серверная часть: `GET/POST/PATCH/DELETE /api/my/listings` с проверкой владельца,
чужое объявление отдаёт 403. У объявления появились поля `status`, `photos`,
`description`, `rules`, `address`, `ownerId`. Черновики и снятые с публикации в
каталог не попадают.

**Заглушка, о которой надо знать:** владелец приходит заголовком `x-user-id`.
Токенов в проекте нет, вход возвращает только пользователя. Когда появится JWT,
меняется одна функция `getUserId`.

## Замены зависимостей

`bcrypt` требует компиляции и не собирается без Visual Studio с C++, поэтому
хеширование идёт через `bcryptjs` — чистый JavaScript, тот же алгоритм.

`better-sqlite3` тоже нативный, но готовые бинарники лежат внутри пакета, в
папке `prebuilds/`. Собирать нечего, достаточно ставить с `--ignore-scripts`:
без флага npm видит `binding.gyp` и всё равно запускает сборку.

Фраза «база пока не подключена вообще» относилась к состоянию до 28 августа.
После перехода Амира на SQLite она устарела: база подключена, шесть таблиц.
