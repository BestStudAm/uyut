# Стек технологий

Что взяли, зачем и от чего отказались. Проект учебный, срок две недели на троих,
поэтому главный критерий выбора один: сколько времени уйдёт на освоение
инструмента по сравнению с тем, сколько он сэкономит.

## Клиент

| Технология | Версия | Зачем |
|---|---|---|
| Next.js (App Router) | 16.3.2 | Роутинг по папкам, готовая сборка и dev-сервер. Не пришлось настраивать бандлер руками |
| React | 19.2.8 | Требование практики. Компонентный подход, вся команда с ним знакома |
| TypeScript | 5.x | Ошибки в полях объявления ловятся до запуска, а не в браузере. Критично, когда трое пишут по одному контракту |
| Tailwind CSS | 4.x | Стили пишутся в разметке, три человека не сталкиваются в общих файлах и не спорят об именах классов |
| Яндекс.Карты JS API | 2.1 | Карта в каталоге и в карточке объекта |
| Vitest | 4.x | Тесты. Один рантайм со сборкой, отдельной настройки не потребовал |
| ESLint + eslint-config-next | 9.x | Ловит ошибки React, которые типы не видят: setState в эффекте, ссылки на ref в очистке |

## Что решили осознанно

**SQL руками, без ORM.** Prisma и подобные экономят время на больших схемах, но
требуют отдельного изучения и генерации клиента. У нас пять таблиц, и обычный
SQL в них читается быстрее, чем цепочки методов. На защите такой код проще
объяснить.

**Схема применяется при старте сервера.** `server/src/db.ts` выполняет
`CREATE TABLE IF NOT EXISTS`, а недостающие колонки досыпает через
`ALTER TABLE`. Отдельной системы миграций нет: она окупается на долгой
дистанции, а у нас проект живёт две недели. Практический эффект — участник
делает `git pull`, запускает сервер, и база сама приходит в актуальное
состояние.

**Файл базы лежит в репозитории.** Так у всех одинаковые данные для
демонстрации. Обратная сторона: файл меняется от любого запуска сайта и при
слиянии веток даёт конфликт, который git не умеет разрешать в бинарнике. Если
проект будет жить дальше — первым делом убрать базу из отслеживания и наполнять
её сидером.

**Состояние поиска живёт в адресе страницы, а не в React.** Ссылку на выдачу с
фильтрами можно переслать, и она откроется в том же виде. Кнопка «назад»
работает как ожидается.

**Фотографии объявлений хранятся строкой `data:image` прямо в базе.** Файлового
хранилища у нас нет, поднимать S3 ради учебного проекта не стали. Чтобы запросы
не распухали, картинки уменьшаются в браузере до 900 пикселей перед отправкой.

**Авторизация упрощена.** Вход возвращает пользователя, токенов нет, владелец
объявления передаётся заголовком `x-user-id`. Это заглушка, и она подписана в
коде: `getUserId` в `server/src/routes/myListings.ts`. Полноценный JWT — первый
пункт доработок, менять придётся одну функцию.

## От чего отказались

| Инструмент | Почему нет |
|---|---|
| Redux, Zustand | Для нашего объёма хватает `useState` и одного контекста для авторизации. Время на освоение не окупилось бы |
| React Query, SWR | Загрузка данных решается своей небольшой обёрткой над `fetch` в `lib/api.ts`. Ещё одна библиотека посреди практики — лишний риск |
| Prisma, TypeORM | Пять таблиц, обычного SQL достаточно |
| CSS Modules | Рассматривали как альтернативу Tailwind. Отказались: при трёх параллельных верстальщиках Tailwind даёт меньше конфликтов в общих файлах |
| Leaflet + OpenStreetMap | Использовали до 29 августа, работает без ключей и ограничений. Перешли на Яндекс ради привычного пользователю вида карты |
| WebSocket, чат | Отдельная большая тема, в срок не укладывалась. Вынесена в доработки |

## Известные ограничения

**Яндекс.Карты без ключа.** API отдаёт карты и без ключа, но по условиям Яндекса
он нужен, и они вправе начать отдавать заглушку. Загрузчик
`client/src/lib/yandexMaps.ts` подхватит `NEXT_PUBLIC_YANDEX_MAPS_KEY`, если его
завести в `.env.local` — код менять не придётся.

**better-sqlite3 требует Node 22.** Это нативный пакет: под свежую 24-ю ветку
готовых бинарников ещё нет, и npm пытается собрать его из исходников, для чего
нужна Visual Studio с компонентом C++. На Node 22 LTS ставится готовым
бинарником за секунды.

**Порты 3000 и 3001 зафиксированы.** Адрес API прописан в
`client/src/lib/api.ts`, а CORS на сервере пускает только `http://localhost:3000`.
Вынести в переменные окружения — тоже в доработки.
