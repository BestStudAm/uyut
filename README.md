# Уют — сервис посуточной аренды жилья

Учебный проект летней практики. Команда из трёх человек, сдача 31 августа 2026.

Пользователь выбирает город и даты, смотрит квартиры списком и на карте, открывает
карточку, бронирует на свободные даты и управляет бронями в личном кабинете.
Владелец может разместить своё жильё.

Подробное описание, границы MVP и распределение работ — в [docs/plan.md](docs/plan.md).
Что и когда менялось — в [docs/changelog.md](docs/changelog.md).

## Быстрый старт

Нужен Node 20 или новее. Зависимости ставятся в двух местах отдельно, workspaces не используем.

```bash
npm --prefix server install
npm --prefix client install
```

Дальше два терминала:

```bash
npm --prefix server run dev
```

```bash
npm --prefix client run dev
```

Клиент откроется на http://localhost:3000, API — на http://localhost:3001.

**Порты менять нельзя.** Адрес API захардкожен в `client/src/lib/api.ts` и в
`AuthContext`, а CORS на сервере пускает только `http://localhost:3000`.

### Тестовый аккаунт

```
почта:  artem@example.com
пароль: 12345678
```

Под ним лежат демо-объявления в разделе «Мои объявления».

Базы данных нет: пользователи и объявления живут в памяти сервера. После
перезапуска остаётся только зашитый пользователь и 40 тестовых объявлений,
всё созданное руками пропадает.

```
    listing/           карточка объекта и бронирование

    owner/             свои объявления и форма размещения
  src/lib/api.ts       единая точка запросов к серверу

  src/lib/             чистая логика: фильтрация каталога

```

## Что готово и чего нет

Сквозной сценарий проходится целиком: регистрация, поиск с фильтрами, выбор дат,
бронирование, просмотр брони в кабинете, отмена.

Работает:

- каталог: поиск по городу, датам и гостям, фильтры по цене, типу, комнатам и
  удобствам, сортировка, пагинация
- все параметры поиска в адресе страницы, ссылку можно переслать
- карта Яндекса с метками-ценами; наведение на карточку подсвечивает метку,
  клик по метке прокручивает список к объявлению
- страница объекта: фотографии, удобства, правила, карта с меткой, отзывы,
  календарь занятых дат, расчёт цены, бронирование
- вход и регистрация, закрытые страницы, выход
- избранное и «Мои бронирования» с отменой
- кабинет владельца: свои объявления, публикация, снятие с публикации, черновики,
  форма размещения с загрузкой фотографий и выбором обложки

Не сделано, идёт в отчёт как дальнейшая доработка:

- свой отзыв оставить нельзя, отзывы приходят сидером и только на чтение
- владелец не подтверждает и не отменяет брони со своей стороны
- оплата, чат с владельцем, соцсети, админка — сознательно вне MVP
- мобильные экраны не рисовались в макете, вёрстка адаптируется без макета

## Договорённости по коду

- `client/src/types/listing.ts` и `server/src/data/listings.ts` описывают один и тот
  же контракт. Меняются только вместе, в одном коммите
- запросы к API только через `client/src/lib/api.ts`, голый `fetch` в компонентах не пишем
- у каждого экрана, который грузит данные, есть три состояния: загрузка, ошибка, пусто
- вёрстка проверяется на ширине 360 пикселей
- цвета и отступы берём из переменных в `client/src/app/globals.css`

## С чего начать читать код

Если разбираетесь в проекте впервые (или подключаете ИИ-агента), порядок такой:

1. `docs/plan.md` — что за продукт, что входит в MVP, а что осознанно вынесено
2. `client/src/types/listing.ts` — контракт данных, вокруг него всё построено
3. `server/src/routes/` — какие есть ручки
4. `client/src/features/catalog/CatalogPage.tsx` — как устроен типичный экран:
   параметры из адреса, загрузка, три состояния, связка списка с картой

Известная заглушка: токенов в проекте нет, вход возвращает только пользователя.
Владелец объявления передаётся заголовком `x-user-id` — см. `getUserId` в
`server/src/routes/myListings.ts`. Когда появится JWT, меняется одна функция.
